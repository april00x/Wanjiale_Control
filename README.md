# Wanjiale Control

把万家乐智能热水器 / 壁挂炉接入 Home Assistant。

- 局域网 + 官方云平台连接，控制与状态查询都优先走局域网，失败回退云端
- 开关机、设定温度、模式切换、零冷水、增压、杀菌、预约等控制
- 用水用气统计与故障代码提示

## 安装

#### 方式一：[HACS](https://hacs.xyz)（推荐）

> HACS > 右上角菜单 > 自定义存储库 > 地址填 `https://github.com/april00x/Wanjiale_Control` > 类别选「集成」 > 搜索 `Wanjiale Control` > 下载

#### 方式二：手动

> 将 `custom_components/wanjiale_control` 整个目录复制到你的 `config/custom_components/`

完成后重启 Home Assistant。

## 配置

添加集成时填官方 App 的账号（手机号）和密码。

集成卡片 > 配置，可进入选项页。选项分为两类：

**账号级设置**（对整个账号生效）

| 选项 | 说明 |
| --- | --- |
| 多端操作权抢占 | 默认关闭。开启后每次控制前会先用登录手机号抢占设备操作权，对应官方 App 的多端互斥机制。机型不校验这一项则无需开启 |
| 重新获取设备 | 一次性动作：勾选并保存后，本次重载会重新从云端拉取设备，使新加入的设备出现在 HA。该选项不会被保存，仅本次生效 |

**按设备设置功能**（只影响所选的那一台设备）

- 取消勾选 = 这台设备不创建该功能的实体（强制关闭）
- 勾选原本没生效的功能 = 创建实体（强制开启）
- 没有改动过的功能保持按能力表自动判定，不会被固化；以后能力表升级、设备重新探测到新功能时会照常出现
- 关闭后对应实体会随重载自动从 HA 实体注册表移除（不会留下灰色不可用实体）；重新勾选会重新创建，期间对该实体做过的重命名、区域等自定义设置不会保留

功能覆盖按设备保存：同一账号下有两台同品类设备时，可以只给其中一台开/关某个功能。

> 从旧版本升级：旧版的功能覆盖存在账号上、没有设备维度。账号下只有一台设备时会在首次加载时自动迁移到这台设备；有多台设备时无法判定归属，旧设置会被忽略，请在「按设备设置功能」里重新配置一次。

首次安装（HA 里还没有本集成的设备）会收编账号下的全部设备；之后云端新增的设备默认不出现，需要勾选「重新获取设备」保存一次。在云平台删除设备不会自动从 HA 移除，请在 HA 里手工删除。

## 说明

- 实体按官方机型能力表+设备实际上报创建，没探测到的功能不会出现实体；拿不准的可以在选项页按设备强制开关
- 状态刷新间隔 10 秒；控制下发后先按预期值更新界面，2 秒内忽略设备回写，避免状态回跳
- 云端登录/会话状态只影响远程控制，不影响实体可用性，局域网能控时，即使云端会话过期，实体仍显示可用
- 设备地址通过局域网广播自动发现，不需要手动设置固定 IP
- HA 下发控制指令大约有 4 秒延迟，官方 App 侧的变更同步到 HA 也差不多

## 注意事项

***❗注意：「累计用水量清零」与「累计用气量清零」是一次性动作，点下去立即下发，无法撤销。Home Assistant 的按钮实体不支持弹出确认框，操作前请确认***

***❗注意：「点动循环」是水控使能开关，不是一次性动作。打开后只要有水流就会自动触发一次即热，可在开关上随时关闭。旧版本中它是只能开、不能关的按钮，升级后遗留的旧按钮实体可在实体列表中删除***

## 调试

要打开调试日志输出，在 configuration.yaml 中做如下配置

```yaml
logger:
  default: warn
  logs:
    custom_components.wanjiale_control: debug
```

集成详情页还提供「下载诊断信息」，可导出一份 JSON 快照，账号与设备标识已脱敏。若怀疑会话问题，重点看 `auth` 块：`state`（OK/DEGRADED/RECOVERING/COOLDOWN/REAUTH_REQUIRED）、`http_ok`、`cloud_session_ok`、`lan_ok`、`daily_logins`、`next_retry_at`、`credential_fail_streak`。

## 常见问题

- **实体比预期少？** 集成按机型能力创建实体，如有缺漏的请反馈。
- **一用水就自动启动即热？** 检查「点动循环」开关是否被打开，关掉即可。
- **没有「冷气泡水」开关？** 该功能只在官方 App 确有气泡水入口的机型上创建，确需使用可在选项页选中这台设备后强制开启。
- **预约时段只能看不能改？** HA 没有原生的时间窗实体，改预约又要成对写起止时间，多端同时写容易冲突，所以只读，要改请用官方 App。
- **设备显示离线？** 现在只有在局域网和云端两条通道连续约 60 秒都取不到数据时才会显示不可用，之后每 60 秒自动重探，恢复供电后 1 分钟内一般会自己回来。若长时间不可用，先确认设备通电、与本机在同一局域网，再在「下载诊断信息」里看 `devices[].query_fail_streak` 与 `cloud_online`：前者持续增长说明两条通道都不通，后者是云端快照，与可用性无关。

- **热水器为什么显示在「空调」分组下？** 这是 Home Assistant 区域页（自动生成的摘要视图）的分组规则，不是集成把设备归类成了空调。区域页的「空调」分组同时收纳 `climate`（空调）、`humidifier`（加湿器）、`water_heater`（热水器）和 `fan`（风扇）四个域，分组标题取的是 `climate` 的中文译名「空调」。设备本身仍是 `water_heater` 域（`water_heater.xxx`），功能和控制都不受影响。
- **区域页里只看到一张调温卡片，没有其他实体** 区域页是摘要视图，「空调」分组只渲染温控类实体，所以一台热水器在这里只出现一张设定温度卡片。开关、模式、零冷水、数值、按钮、传感器等实体都在同页的其他分组或设备的「实体」列表里（设置 → 设备与服务 → 设备 → 点设备名 → 实体）；诊断类实体（设定温度原始值、水流量、水量档位等）默认不在自动视图展示。
- **同一台设备出现了两次？** 如果这台设备同时通过米家等其他集成接入，HA 里会有两台同名设备（例如都叫「燃热U9 MAX」）。建议只保留一个集成并禁用另一个，避免重复控制和状态不一致。

## 已知限制

- 部分功能未在真机验证
- CO 状态、堵塞条件只有数值范围没有取值枚举，只显示原始值，不做告警判断，避免误报
- 水压、气压、电压、风压、水阀只有少数机型会上报，跨机型含义不一致，暂时未能解析
- 燃气壁挂炉（002）尚未在真机验证，未定案的协议歧义点见 [gas_boiler.md](doc/gas_boiler.md#未验证项) 的未验证项清单
